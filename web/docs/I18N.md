# Lazy Balancer V2 多语言（i18n）标准

> 本文档是多语言实现的**唯一标准**。后续所有功能开发（前端与后端）都必须遵循。
> 违反本标准的代码无法通过 build 门禁（多个守卫测试钉住关键契约）。

## 1. 架构总览

```
vue-i18n 单例（src/i18n/）
├── tSafe（../i18n/tSafe.ts）    # 组件内安全取词：未命中返回键本身，不抛错
├── locales/{zh,en}/settings.ts  # 页面域词条（settings/views/rules/security/...）
├── locales/{zh,en}/common.ts    # 跨页共用词条（弹框按钮/通用名词）
└── locales/{zh,en}/views.ts     # 视图级词条（dashboard/cluster/proxyTimeout...）
```

- **语言切换**：`lb_locale` localStorage + vue-i18n `locale` ref；`html[data-locale]` 属性驱动 CSS 分语言样式（如 `.tip-nowrap` 仅 en 生效）。
- **locale 值域**：`zh-CN` / `en`。判断语言一律用 `locale.startsWith('zh')`，**禁止** `locale === 'zh'`（实测踩坑：data-locale 为 zh-CN）。
- **词条键路径**：必须与组件读取路径**同域**。词条插错子块（如把 `basic.restoreResult.*` 插进 `basic.autoBackup.*`）= 裸键线上事故，录入前必须核对渲染端 `t()` 的完整键路径。

## 2. 前端规范（强制）

### 2.1 词条
1. 所有用户可见文本一律走 `t()`/`tSafe`，**禁止硬编码中文/英文**于模板或消息。
2. 新增词条：zh/en **双语同批提交**（只提交单语 = 另一语言裸键，属线上事故）。
3. 词条键用 camelCase；结构块按功能域嵌套；插错域 = 键路径不一致，先 grep 渲染端 `t('...')` 完整键再落位。
4. 展示映射表（如省名/国名/分类名）：
   - 读取必须走 `hasOwn`（原型键守卫——`vocabularyProtoKeys` 守卫测试扫描 `const X: Record<string, …>` 与 `= computed<Record<string, string>>` 形态）；
   - 派生缓存表（非静态展示词表）**不要**用 `computed<Record<string, string>>` 注解形式声明（出扫描面），但读取仍按契约走 hasOwn；
   - 词条未覆盖的外部数据键（IP 库采样条目等）必须 **fallback 原名**（判 `t()` 结果含 `app.` 前缀即裸键）。

### 2.2 数字/日期/文件名
1. 日期时间一律走 `src/utils/date.ts`（`formatDate`/`formatDateShort`，**配置时区**）——禁止 `toISOString()`（UTC）用于展示与文件名（`settingsWiringContracts` 守卫钉住）。
2. 导出文件名时间戳口径：`YYYYMMDD-HHMMSS`（与后端 `Content-Disposition` 同构），同日多次导出不重名。

### 2.3 样式
1. 行内 tip（`form-tip-inline`）默认 nowrap；`tip-nowrap` 类语义 = **解除 nowrap 允许折行**（仅 en）——反直觉命名，改样式前先读 `main.css` 注释。
2. 文案放不下的处理顺序：**先精简文案**（通俗直观，删占位符语义）→ 信息降级（次要语义移 `:title` 悬浮）→ 结构化换行样式（`form-tip-line`，用户逐项裁定后才用）。
3. 双语长度差异大时可按 locale 分流样式（`v-if="locale.startsWith('zh')"` 行内 / else tip-line）——需用户裁定后使用。

### 2.4 build 门禁相关守卫（会拦截违规）
| 守卫 | 钉住的契约 |
|---|---|
| `vocabularyProtoKeys.spec` | 词表读取过 hasOwn；无读取点=死表拒绝 |
| `settingsWiringContracts.spec` | 导出文件名配置时区；禁 toISOString |
| 各 `*Layout/Ui.spec` | 关键页面结构契约（改动布局先读对应 spec） |

**提交前必须 `npm run build`（含全部守卫）**——只跑 typecheck/test:coverage 会漏守卫（实录：finalize 才拦下）。

## 3. 后端现状与规划

- 现状：`message`/`warnings`（导入/还原统计、规则警告、封禁变更等）为 **zh 硬编码**，分布于 `config_backup_lbbak.go` / `autoban.go` / `helpers.go` 等处；en 面板当前展示 zh 数据文本。
- 规划（待办工程）：后端按请求 locale（`Accept-Language` 或面板透传的 locale header）生成双语 `message`/`warnings`；模板集中单源（对齐 `geoipnames.CountryNamesCN` 的表驱动范式），前端零改动消费。
- 过渡期约定：前端结构化弹框（徽章/提示/警告分区）已双语；数据文本回落 zh 不阻塞。

## 4. 新增功能多语言 checklist（每轮必过）

- [ ] 模板/消息零硬编码文案，全部 `t()`
- [ ] zh/en 词条同批新增，键路径与渲染端 `t()` 同域核对
- [ ] 展示映射表：hasOwn 守卫 + 裸键 fallback 原名
- [ ] 双语实测：切换 `lb_locale` 打开目标 UI 各验一次（裸键计数=0、无中文泄漏/无英文泄漏按语言判定）
- [ ] 日期/文件名走配置时区工具，未引入 toISOString
- [ ] `npm run build` 全绿（含守卫）
