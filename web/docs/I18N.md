# Lazy Balancer V2 多语言（i18n）标准

> 本文档是多语言实现的**唯一标准**。后续所有功能开发（前端与后端）都必须遵循。
> 违反本标准的代码无法通过 build 门禁（多个守卫测试钉住关键契约）。

## 0. 架构裁定（最高优先级，优先于本文其余各节）

**裁定（2026-11-25，项目所有者）：后端返回统一标准的状态码，前端根据选择的语言展示即可。**

**原始设计记录**：2026-11-09 项目所有者确认「方案 C：键化存储 + 分步走」（设计笔记 `.omp/local/audit-i18n-design.md`，本机文件）。要点：
- 后端以「键 + 参数」作为标识来存储与传输（审计明细为 `detail_key` / `detail_params`），可同时保留中文原文作兼容与兜底。
- 前端有键就按当前语言用自己的词条渲染，缺键回落原文；**前端不依赖后端翻译**。
- 分步迁移；存量中文行不迁移，混存期可接受；明细按文本搜索的降级可接受。
- 落地进度（2026-11-25 核对）：仅第 1 步（枚举的前端映射）落地。第 2 步明细键化未实施（代码中无 `detail_key` / `detail_params`），审计明细仍是后端拼好的中文整句。

由此确定的规则：
1. **展示文案只归前端。** 界面上出现的每一种语言的文案，来源都是前端词条（`t()`）。后端不产出面向界面的展示文案：不按请求语言返回译文，不登记 zh→en 展示模板。
2. **后端只返回语言无关的标识与数据。** HTTP 状态 + 业务码 + 稳定语义键 + 结构化参数/数据。标识一经发布不得随文案调整而变化。
3. **前端只用语言无关的标识做映射与判断。** 不得把后端返回的中文文本当映射键，也不得对后端整句做子串或正则判断。
4. **发现英文界面出现后端中文时，修法在前端或在标识层**（前端补词条 / 后端补稳定键与参数），**不是在后端补翻译**。

禁止（防复发，均为 2026-11-25 实录）：
- 把「英文界面不得出现中文」当成沿「后端翻译」路线继续加固的授权——那是目标裁定，不是机制授权。
- 为后端新增展示译文登记（`internal/i18n` 的 catalog 与错误模板），或扩展 `internal/apimsg` / `i18n.TrErr` 的匹配能力（嵌套实参、列表实参、运行期普查门禁等）。
- 把本文件里的「现状 / 已落地」段落当成架构裁定——那些只描述实现。
- 架构级的机制选择（哪一层负责什么）未经项目所有者确认不得落地；拿不准时先回滚再呈报，不要猜设计细节。

**现状声明：仓库内自 2026-11-09 起落地的后端双语机制**（`internal/i18n` 的 catalog 与 zh→en 错误模板、`internal/apimsg`、语言协商中间件、按 `Accept-Language` 返回译文）**偏离本裁定，属于待迁移的遗留，不是可以沿用的标准。** 在本次修订前，第 3 节曾把它写成「后端现状（双语已落地）」。

迁移方向（细则须经项目所有者审定后另行成文）：
1. 前端建立「稳定键 → 词条」映射（现有 catalog 的 zh/en 可机械导出到前端词条），显示时按键取词条，缺键回落原文。
2. 带参数的动态消息（规则校验、证书/CA、导入还原告警等）改为「稳定键 + 结构化参数」，模板在前端。
3. 后端逐步停止按请求语言返回译文。
4. 审计明细按方案 C 第 2、3 步键化。

裁定进展（2026-11-25，项目所有者）：
- 语义键的形态：`域名.驼峰名`（如 `rule.versionConflict`），不随措辞变化，不保留旧键兼容期；后端全目录与调用点已改名。
- 后端 `message` 字段：保留中文原文作兜底，不再翻译。
- 迁移顺序：先让前端不再依赖后端翻译，再改中文枚举值，最后后端收尾。
- 通知投递内容：不属本次迁移（项目所有者口径：通知正文模板已支持多语言）。
- 带参数消息：沿用方案 C 的口径——后端回传键 + 参数、保留中文原文兜底、模板在前端；响应里参数字段的具体形态随该步实施时写进本节。

## 1. 架构总览

```
vue-i18n 单例（src/i18n/index.ts）
├── src/i18n/tSafe.ts            # 组件外安全取词：委托主实例，未命中返回键本身，不抛错
├── src/locales/{zh,en}/common.ts   # 跨页共用词条（弹框按钮/通用名词/api 消息）
├── src/locales/{zh,en}/settings.ts # 设置域词条
├── src/locales/{zh,en}/views.ts    # 视图级词条（dashboard/cluster/trigDetail...）
├── src/locales/{zh,en}/rules.ts    # 规则域词条
├── src/locales/{zh,en}/security.ts # 安全域词条
└── src/locales/{zh,en}/misc.ts     # 其余散域词条
```

- **语言切换**：`lb_locale` localStorage + vue-i18n `locale` ref；`html[data-locale]` 属性驱动 CSS 分语言样式（如 `html[data-locale='en'] .form-tip-inline` 解除 nowrap 仅 en 生效）。
- **locale 值域**：`zh-CN` / `en`。判断语言一律用 `locale.startsWith('zh')`，**禁止** `locale === 'zh'`（实测踩坑：data-locale 为 zh-CN）。
- **词条键路径**：必须与组件读取路径**同域**。词条插错子块（如把 `basic.restoreResult.*` 插进 `basic.autoBackup.*`）= 裸键线上事故，录入前必须核对渲染端 `t()` 的完整键路径。

## 2. 前端规范（强制）

### 2.1 词条
1. 所有用户可见文本一律走 `t()`/`tSafe`，**禁止硬编码中文/英文**于模板或消息。
2. 新增词条：zh/en **双语同批提交**（只提交单语 = 另一语言裸键，属线上事故）。
3. 词条键用 camelCase；结构块按功能域嵌套；插错域 = 键路径不一致，先 grep 渲染端 `t('...')` 完整键再落位。
4. 展示映射表（如省名/国名/分类名）：
   - 读取必须走 `hasOwn`（原型键守卫——`vocabularyProtoKeys` 守卫测试扫描 `const X: Record<string, …>` 与 `= computed<Record<string, string>>` 形态）；
   - 派生缓存表（非静态展示词表）**不要**用 `computed<Record<string, string>>` 注解形式声明（出扫描面），但读取仍按契约走 hasOwn；
   - 词条未覆盖的外部数据键（IP 库采样条目等）必须 **fallback 原名**（判 `t()` 结果含 `app.` 前缀即裸键）。

### 2.2 数字/日期/文件名
1. 日期时间一律走 `src/utils/date.ts`（`formatDate`/`formatDateShort`，**配置时区**）——禁止 `toISOString()`（UTC）用于展示与文件名（`settingsWiringContracts` 守卫钉住）。
2. 导出文件名时间戳口径：`YYYYMMDD-HHMMSS`（与后端 `Content-Disposition` 同构），同日多次导出不重名。

### 2.3 样式
1. 行内 tip（`form-tip-inline`）默认 nowrap；en 全局规则解除 nowrap 允许折行。CaddyGlobalSettings 的 `tip-wrap` 类语义 = **允许折行 + 长词可断**（white-space:normal + overflow-wrap:anywhere，全 locale）——旧名 `tip-nowrap` 与实现相反已退役，改样式前先读 `main.css` 与组件内注释。
2. 文案放不下的处理顺序：**先精简文案**（通俗直观，删占位符语义）→ 信息降级（次要语义移 `:title` 悬浮）→ 结构化换行样式（`form-tip-line`，用户逐项裁定后才用）。
3. 双语长度差异大时可按 locale 分流样式（`v-if="locale.startsWith('zh')"` 行内 / else tip-line）——需用户裁定后使用。

### 2.4 build 门禁相关守卫（会拦截违规）
| 守卫 | 钉住的契约 |
|---|---|
| `vocabularyProtoKeys.spec` | 词表读取过 hasOwn；无读取点=死表拒绝 |
| `settingsWiringContracts.spec` | 导出文件名配置时区；禁 toISOString |
| 各 `*Layout/Ui.spec` | 关键页面结构契约（改动布局先读对应 spec） |

**提交前必须 `npm run build`（含全部守卫）**——只跑 typecheck/test:coverage 会漏守卫（实录：finalize 才拦下）。

## 3. 后端现状（偏离第 0 节裁定的遗留，待迁移）

> 本节只描述**已提交代码的现状**，供迁移时盘点，不是标准。规范以第 0 节为准：后端只返回稳定码/键与结构化数据，展示文案归前端。不得沿用下列机制继续扩展。

- 2026-11-09 起落地的后端双语机制（提交 `853665e9`、`1b6fcc87`）：
  - **语言协商**：`internal/middleware/i18n_lang.go` 从 `Accept-Language` 解析目标语言（仅 zh/en，其余回落 zh）写入上下文，并回 `Content-Language` 响应头；前端请求拦截器按当前 locale 发送该头。
  - **消息取用**：handler 经 `internal/apimsg`（`apimsg.T(c, "auth.mfaChallengeInvalidOrExpired")` / `apimsg.Tf(c, "backup.importEmptyDomainRulePolicyBindingsSkipped", args...)`）取词条；响应信封同时携带稳定语义键 `MessageKey`（wire 字段 `message_key`，形态 `域名.驼峰名`）。前端目前只把它用于语言无关分类（如退化 200 `security.savedButCaddyApplyFailed`），不用它取显示文案。
  - **词条与错误模板**：`internal/i18n/catalog_gen.go` 与 `catalog_manual.go`（zh 母本 + en 译文，手工维护）；`errtpl_gen.go` 登记服务层错误的 zh→en 模板，运行时按字符串模板匹配 Go 错误串。
- 规模（2026-11-25 盘点）：键化调用 917 处、zh→en 模板 759 条、回传 `message_key` 789 处。
- 已知的遗留缺口（迁移时须覆盖）：未键化的中文字面量约 397 处；变量 / `err.Error()` / 辅助函数等非字面量写法约 116 处；服务层运行时拼出的消息，测试可触达的片段 756 条；后端写入 `data` 的中文展示文本 18 组（操作日志 `detail`、任务监控 `description` 与 `last_run.message`、默认策略/名单/拦截页名称、DNS 提供商字段、归属地与攻击族名、集群同步错误等）。这些正是「后端产出展示文案」这一层选择的代价，应通过迁移消除，而不是逐条补翻译。
- 新增后端消息：按第 0 节返回稳定码/键与结构化参数，界面文案在前端词条同批新增。不再新增后端展示译文。
