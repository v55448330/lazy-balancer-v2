# 行为研判与自动封禁 · 独立设计方案（归档备用，2026-09-25 用户提议并裁定：暂不实施）

> 状态：**设计归档，未实施**。与 XDP 前置防护（docs/xdp-prefilter-design.zh-CN.md）
> 相互独立——可单独立项、单独交付、单独开关；两案无依赖关系。
> 需求原点：根据请求行为自动判断恶意请求并自动封禁，维护自动封禁 IP 地址列表。

## 1. 前提与边界（诚实基线）

- **AI/LLM 不进请求热路径**：判定预算 82ns（@ipListFast）~µs（Caddy），
  LLM 推理百毫秒~秒级，差六个数量级——内联 AI 判分物理不成立。
  可行形态 = **近线研判管线**（批处理事件/日志 → 评分 → 自动封禁名单）。
- **不自研特征规则库**：特征扫描斗不过 CRS（CRS 就是特征库）——判断交给
  决策模型（Jev），本地只保留离线兜底评分卡。对外文案不得把本能力包装成
  「AI 驱动」主卖点——决策模型只是管线一环，名单生命周期与护栏才是主体。

## 2. 研判管线（Jev 决策模型版，2026-09-25 重构——用户裁定：特征扫描不合理，自研特征库不会强过 CRS；事件均为已拦请求，价值定位=资源救济/防线前移/降噪）

### 2.0 价值定位（诚实口径）

自动封禁**不是新防护能力**（已被拦的请求再封 IP 边际安全收益有限），真实价值：
①重复泛洪的连接/带宽/CPU 开销归零；②探测期掐断（不等新载荷出现）；
③告警降噪。方案全文按此定位，不夸大。

### 2.1 决策引擎：Jev（TypeSafe AI System One 模型，jev-1.13.0）

- 形态：不生成文本——输入行为状态摘要+类型化问题，返回结构化判断
  {ban: bool, confidence: 校准概率, reason_code: 枚举} + 校准概率。
- 实测口径（厂商基准）：0.114s/决策、$0.000081/决策——比传统 LLM 快 ~194 倍、
  便宜 ~445 倍；**仍不进热路径**（0.1s 对 82ns 判定预算依然是天文数字），
  全部近线批量执行。
- 替换关系：原三层（L1 启发式规则表/L2 加权评分卡/L3 LLM）合并为本层——
  不再自研特征规则（那正是「自己写特征库」，斗不过 CRS）。

### 2.2 管线（60s tick，master-only，复用 threatscheduler 调度模式）

1. **候选圈定**（粗阈值，纯 SQL 聚合）：窗口内 ≥1 安全事件 或 ≥30 请求的 IP。
2. **行为状态摘要**（非签名，是统计+采样）：速率曲线、错误率、事件史
   （action/rule_msg 族/异常分序列）、路径样本（参数脱敏）、UA 族、
   威胁库命中史、24h 复现天数。
3. **批量喂 Jev**：类型化问题+校准概率。
4. **裁决门**：confidence ≥85 写自动封禁名单；70–84 观察名单（下周期重评）；
   <70 释放。校准阈值面板可调。
5. **dry-run 默认起步**：先「只建议不封」运行，面板实测 Jev 在本部署真实
   流量上的精确率/召回率（对比用户手动裁决），用户确认后才转正式——
   Jev 发布于 2026-09-15，WAF 遥测域无第三方校准记录，必须用自家数据验证。

### 2.3 本地兜底层（离线降级，非主力）

Jev 端点故障/未配置时，退化为**加权评分卡**（纯 Go、可解释：速率熵/错误率/
复犯计数加权，阈值可调）——保证「无外部依赖时管线仍可运行」，但面板明示
其精度低于 Jev 实测口径。评分卡不追求强，只追求「不断流」。

### 2.4 隐私与成本

- 行为摘要外发需显式授权（隐私确认弹框）+ 路径参数脱敏；密钥走现有全局
  配置面（github_token 三态同款）。
- 成本：每万候选/天 ≈ $0.81；面板显示累计决策数与估算成本。
- Jev 端点故障 → 自动降级本地评分卡 + 面板横幅，不阻塞名单生命周期。

## 2.5 可行性评估（2026-09-25 调研，含厂商口径折扣）

- **形态契合**：Jev 类型化问题（Choice/Score/Noul，一次调用多问题并行带概率）
  与本场景裁决集一一对应；32k 上下文；$0.042/百万输入 token（输出免费），
  日万候选成本 <$0.25；已上架 OpenRouter/Cloudflare Workers AI（备用通道）。
- **三硬约束**：①纯云端无自托管（权重未公开）→ 隐私敏感用户群不可用，
  本功能恒为可选开关、本地兜底必留；②发布 10 天、全部基准为厂商自测、
  零独立复测 → dry-run 精度实测门为强制前提；③训练域为工作流决策，
  WAF 遥测判断不在已知分布内——只能自家流量实测。
- **效果预估（分场景，不打鸡血）**：明显惯犯与平凡规则打平（不需要 AI）；
  灰区行为（拟人爬虫/低速探测）是主战场，预期显著优于手写权重；低慢定向
  攻击基本无效（统计窗口物理限制）；整体=消 80–90% 扫描噪声，安全防护
  增益边际。上限由「事件均为已拦请求」的数据前提决定，不由模型决定。
- **变量**：开源对标已出现（GLiFormer/jeff 声称追平）——若可自托管决策模型
  成熟，隐私约束消失，方案可从「可选」升「默认可开」；决策层按接口抽象
  设计（Jev 只是第一个实现）。

## 3. 自动封禁名单（与既有威胁情报库同构——本方案的最大杠杆）

- 新增系统级 IP 列表「**自动封禁名单**」（security_ip_lists，system=1，与
  中科大/FireHOL/ET 三个威胁源同机制）：条目带 `expires_at` 与 `confidence`，
  由研判管线写入；策略侧按现有「引用名单」机制一键引用，渲染走
  @ipListFast 投影，更新命中既有「名单变化且被引用才重载」门——
  **执行链零新增**。
- 开放协同（非依赖）：若 XDP 前置模块未来实施，同一名单可经其端口聚合
  模型灌内核 LPM trie——单一数据源供双执行面。

## 4. 安全护栏（误封是本项目最大的产品风险，全部硬性）

1. **dry-run 模式**：管线先以「建议封禁」运行（只记录不生效），用户在
   面板观察建议准确率后手动转正式——默认从 dry-run 起步。
2. **TTL 与衰减**：封禁必带过期（默认 24h，可配）；持续作恶续期、
   安静自动解封。
3. **保护名单**：信任名单、管理员最近登录 IP、内网段（RFC1918/ULA）
   永不被封。
4. **反馈环**：用户手动解封某 IP → 该 IP 进抑制清单（30 天不再自动封）；
   误封率统计进面板。
5. **审计留痕**：每次封/解封落审计日志（来源层 L1/L2/L3、置信度、证据
   摘要指针）。
6. **CDN/受信代理语义**：研判以真实 IP（受信代理还原后）为准——CDN 场景
   按回源 IP 封禁等于封 CDN 节点，strict 模式下伪造头不进特征。

## 5. 面板形态（若立项）

- 「安全防护 → IP 地址列表」新增系统名单卡「自动封禁名单」（只读查看+
  手动解封入口），同威胁情报库卡片族。
- 研判管线状态卡：dry-run/正式开关、今日建议/封禁/解封计数、误封反馈率。
- 配置面：L1 阈值、TTL、L3 端点与密钥（默认关）。

## 6. 里程碑

1. **B1**：本地兜底评分卡 + 自动封禁名单 + dry-run + 护栏（纯本地零外发；
   执行链复用现有名单机制——本体工作量最小）。
2. **B2**：接入 Jev 决策层（候选圈定+状态摘要+批量裁决）+ 精度实测面板
   （dry-run 对照用户裁决）+ 误封反馈环。
3. **B3**：Jev 转正式的精度门（实测精确率达标才允许开启）+ 成本审计视图。

## 7. 风险登记

| 风险 | 等级 | 缓解 |
|---|---|---|
| 误封合法用户（NAT 出口/运营商共享 IP/移动网络） | **高** | dry-run 默认 + TTL + 保护名单 + 反馈抑制（§4 全组） |
| Jev 成本与隐私（行为摘要外发） | 中 | 默认关+显式授权+脱敏+成本计数；离线兜底层保底 |
| 自动封禁被滥用做反射（攻击者诱导封禁第三方 IP——X-Forwarded-For 伪造） | 中 | 研判只信受信代理还原链（strict 模式下伪造头不进特征） |
| 名单膨胀（自动封禁条目无界增长） | 低 | TTL 自然收敛 + 条目上限（超上限按置信度淘汰低分项） |
