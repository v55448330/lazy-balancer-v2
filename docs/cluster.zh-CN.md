# 集群管理

## 部署步骤

1. 主节点：集群管理 → 生成注册令牌（一次性，30 分钟有效）
2. 从节点：选择「从节点」，输入主节点地址 + 令牌注册
3. 主节点：在节点列表点击「确认」
4. 从节点开始同步并周期上报；全只读，可「提升为主节点」脱离集群

主节点配置变更自动递增集群版本；从节点按节哈希增量同步（规则/证书/用户/密钥/设置/安全策略均在范围内）。

**同步范围开关**（主节点设置）：系统数据（用户/密钥/证书/ACME）恒同步不可禁用、排第一位；全局配置（含品牌文案 branding）、负载均衡规则、规则库数据库（CRS/IP2Region 文件与版本行）、安全策略规则可按需开关。branding.json 修改经全局配置通道自动同步到从节点生效；从节点本地手改会被下次同步覆盖（主节点为准）。

## MFA 两步验证

TOTP（Google/Microsoft Authenticator），在设置 → 基础设置 → MFA 卡片自助绑定（二维码 + 10 个恢复码）。登录后零密码输入；写操作验证与失败锁定为可选全局开关（默认关闭）。

## 安全模型

- 集群令牌与 CA/DNS 凭证明文存于 `data/lazy-balancer.db`（启动强制 0600/0700），勿共享挂载
- 通信默认 HTTPS + TOFU 指纹钉扎防中间人；可信网络可明文（带审计警告）
- 重新生成注册令牌即刻作废全部未使用令牌

## Pin 不匹配恢复

主节点更换管理面板证书后，从节点报 `PinMismatch` 拒绝同步。管理员在从节点调用 `POST /api/v1/cluster/forget-pins` 清除已记指纹，下次同步自动重新钉扎。

## 升级须知

集群升级建议主从同窗口完成。滚动升级窗口内安全数据哈希可能不匹配（自愈）；跨 schema 升级时旧从节点报版本不兼容为预期安全拒绝。
