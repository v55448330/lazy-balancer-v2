# OIDC 登录认证指南

> 适用版本:v2.3.0+

Lazy Balancer 支持通过 **OIDC(OpenID Connect)** 对接企业认证服务,实现单点登录。本文介绍功能原理、配置步骤,并以 **Microsoft Entra ID**(原 Azure AD)为例给出完整示例。

## 功能概述

### 什么是 OIDC 登录

OIDC 是构建在 OAuth 2.0 之上的身份认证协议。配置后,用户点击登录页的「企业认证服务」按钮,跳转到认证服务完成登录,认证通过后自动返回本系统——无需在本系统内维护第二套密码。

### 设计要点

| 特性 | 说明 |
|---|---|
| 单提供商 | 当前支持配置 1 个 OIDC 提供商(4 项核心配置) |
| 端点自动发现 | 只需填服务地址,授权/令牌/JWKS 端点经 Discovery 文档自动获取 |
| 独立开户 | OIDC 用户与本地账号**完全独立**——即使邮箱相同也不绑定;首次登录自动创建账户(默认「用户」角色) |
| 本地登录保底 | OIDC 启用后登录页仍保留本地账号入口(默认折叠),管理员密码登录始终可用 |
| 与本地 MFA 解耦 | OIDC 用户的二因子由认证服务侧承担;本系统的 MFA 绑定/写保护/登录锁定仅对本地账号生效 |
| 集群同步 | OIDC 配置随集群快照自动同步到从节点,双节点回调地址均需在认证服务登记 |

### 安全机制

- 标准 Authorization Code Flow + **PKCE**(S256)
- `state` 防 CSRF、`nonce` 防重放,令牌签名经 JWKS 验证
- 回调失败**不计入登录锁定计数**(防止外部攻击者恶意锁号)

## 配置步骤

配置入口:**用户与认证** 页 → 用户列表卡头右侧 →「配置 OIDC」按钮。

### 第一步:填写服务地址

输入认证服务的 OIDC Issuer 地址(以 `https://` 开头)。失焦后系统自动探测 Discovery 文档(`/.well-known/openid-configuration`),绿勾表示发现成功。

> 提示:Microsoft Entra 地址形如
> `https://login.microsoftonline.com/{租户ID}/v2.0`。若漏填 `/v2.0` 后缀,系统会自动补全。

### 第二步:在认证服务后台创建应用

按弹框中展示的信息登记(点击「复制」即可):

| 登记项 | 值 |
|---|---|
| 回调地址(每个节点各一条) | 弹框按**真实集群节点清单**展示——本节点 + 各已审批从节点(access_url 优先),逐条复制登记 |
| 授权范围 | `openid` `profile` `email` |

> 主从部署务必**每个节点的回调地址都登记**(Entra 重定向 URI 支持添加任意多条),否则对应节点 OIDC 登录回调失败;单机部署只需本节点一条。

### 第三步:填入应用凭证

| 字段 | 说明 |
|---|---|
| Client ID | 应用(客户端)ID |
| Client Secret | 应用密钥;已保存过则留空表示保持不变 |
| 显示名(选填) | 登录页按钮文案,默认取服务域名 |

### 保存与验证

1. 点「**测试连接**」——验证服务地址可发现、凭证格式合法
2. 点「**保存并启用**」——保存后登录页即出现认证服务入口
3. 用一个测试账号走一遍完整登录,确认自动开户与角色符合预期

日常管理:「OIDC 设置」弹框内可**暂停使用**(登录入口隐藏,本地登录不受影响)、更新配置、**删除配置**(已创建的 OIDC 用户保留,可在用户列表继续管理)。

## 以 Microsoft Entra ID 为例

### 1. 注册应用

1. 登录 [Microsoft Entra 管理中心](https://entra.microsoft.com) → **标识** → **应用程序** → **应用注册** → **新注册**
2. 名称:如 `Lazy Balancer`
3. 受支持的帐户类型:按需选择(通常「仅此组织目录中的帐户」)
4. 重定向 URI(可选):**Web** 平台,填入两条回调地址,例如:
   ```
   https://lb.example.com/api/v1/auth/oidc/callback
   https://lb-slave.example.com/api/v1/auth/oidc/callback
   ```
   (或在注册后于「身份验证」页补录;本系统弹框中展示的地址可直接复制)

### 2. 创建客户端密钥

「证书和密码」→ **新客户端密码** → 复制生成的**值**(Client Secret,只显示一次)。

### 3. 记录信息

「概述」页:

- **应用程序(客户端) ID** → 填入 Client ID
- **目录(租户) ID** → 拼出服务地址:
  ```
  https://login.microsoftonline.com/<租户ID>/v2.0
  ```

### 4. 回 Lazy Balancer 配置

用户与认证 → 配置 OIDC:

| 字段 | 填写 |
|---|---|
| 服务地址 | `https://login.microsoftonline.com/<租户ID>/v2.0` |
| Client ID | 应用程序(客户端) ID |
| Client Secret | 第 2 步创建的密码值 |
| 显示名 | 如 `Microsoft 登录`(选填) |

测试连接 → 保存并启用。登录页将出现「Microsoft 登录」按钮;用 Entra 账号首次登录即自动创建本系统账户(普通用户角色)。

### 5. 提升 OIDC 用户权限(可选)

自动开户默认「用户」角色。如需管理员:用户与认证页找到该用户 → 编辑 → 角色改为「管理员」。

## 用户管理说明

| 项 | 本地用户 | OIDC 用户 |
|---|---|---|
| 登录方式 | 用户名 + 密码(+MFA) | 跳转认证服务 |
| 密码 | 本系统管理 | 由认证服务管理(本系统不存) |
| MFA 绑定/重置 | 支持 | 不适用(403) |
| 来源列标识 | 本地 | OIDC |

禁用 OIDC 用户的效果:该用户下次 OIDC 登录被拒;已签发的会话在过期前仍有效(与本地用户禁用行为一致)。

## 常见问题

**Q:测试连接报「发现失败」?**
检查服务地址网络可达性(容器需能访问外网认证服务);Entra 用户须确认租户 ID 正确、地址带 `/v2.0`。

**Q:登录回调报错?**
优先检查回调地址是否已在认证服务登记齐全(双节点各一条);其次检查 Client Secret 是否过期(Entra 密码有有效期,到期需换新)。

**Q:OIDC 登录的用户能改用密码登录吗?**
不能。OIDC 用户在本系统无密码(bcrypt 恒空),密码登录天然不可用;反之本地用户也不会出现 OIDC 登录入口身份。

**Q:暂停 OIDC 后已有登录会话?**
已签发会话在过期前继续有效;仅新的 OIDC 登录入口隐藏。
